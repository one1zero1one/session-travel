Phases at a glance

OAuth (one-time)

Claude.ai discovers session-travel, performs Dynamic Client Registration, Dani authorizes in a browser, tokens are exchanged and persisted in a Docker volume. Future calls just use the access token (refresh as needed).

Phase 1 — Ship

Inside Claude Code, /ship reads the session JSONL, spawns Haiku subagents to summarize tool calls, then calls ship_context on the MCP server. Server writes the context slot.

Phase 2 — Pick up (voice)

On the phone, Claude.ai voice calls pickup_context. The server returns the payload from the context slot. Voice now has full session context and continues the conversation.

Phase 3 — Conclude

After discussion, voice synthesizes a structured markdown record (Summary / Decisions / Next Steps / Open Questions) and calls ship_conclusion. Server writes the conclusion slot.

Phase 4 — Return

Back in Claude Code, calling pickup_conclusion retrieves the conclusion slot. The decision record lands in the new session and work continues with state intact.

Two-slot model

  • context slot — outbound from Claude Code, inbound to voice. Written by ship_context, read by pickup_context.
  • conclusion slot — outbound from voice, inbound to Claude Code. Written by ship_conclusion, read by pickup_conclusion.
  • Slots are independent — old context isn't overwritten by a new conclusion, and vice versa.

Why this design

  • Asymmetric clients. Claude Code can read its own JSONL and spawn subagents; voice can't. Pre-summarizing on the Claude Code side keeps the voice prompt small enough to be useful.
  • Structured conclusion. Forcing voice to emit Summary / Decisions / Next Steps / Open Questions makes the return trip durable — not just a vibes transcript.
  • Persistent tokens. Docker volume holds DCR registration and OAuth tokens, so the phone keeps working across server restarts without re-authorizing.
  • Tiny surface. Four MCP tools, two slots. Anything more would just be state to lose.

MCP tools

  • ship_context — write context slot (called by Claude Code /ship)
  • pickup_context — read context slot (called by Claude.ai voice)
  • ship_conclusion — write conclusion slot (called by Claude.ai voice)
  • pickup_conclusion — read conclusion slot (called by Claude Code)
